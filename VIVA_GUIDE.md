# RankLab Viva Demonstration Guide

## 1. Start with the model, not the answer

Open RankLab and point out the six-page demo network: Home, Research, Tutorials, Projects, Resources, and Contact. Contact is dangling in the starting graph, while Research and Tutorials participate in a cycle. Say that the app uses a column-stochastic matrix, so a column describes how one source page distributes its score to destination pages. Run the current model and read the top page, iteration count, tolerance, and final L1 difference from the instrument header.

## 2. Demonstrate graph editing and the network effect

In Network Studio, select Research and show its incoming and outgoing links. Add one directed link from Contact to Research, or remove a link from Home, then point out the amber stale-result badge. Run PageRank again. In Ranking Explorer, show the score and rank movement. Explain that the new edge changes the score distribution from its source page; later iterations carry that difference through other links, so pages that were not endpoints can also move.

## 3. Explain convergence visually

Open Convergence Observatory. The line is the actual L1 difference after each update, not a fabricated curve. Point to the horizontal tolerance threshold and the final stop point. Use Step-through mode to move from the uniform vector at `k = 0` to the final vector, then click a page to show its score trace. Explain that a smaller tolerance asks for a closer successive-vector match and commonly requires more updates, although exact counts depend on the network.

## 4. Open the mathematics progressively

In Mathematics Lab, open Adjacency matrix A first. Use the selected page highlight to explain the source-column convention. Open Transition matrix P and show that each column sums to one. Open Dangling-column correction and point out Contact's uniform replacement column. Then open the Damped Google update and state that damping combines a link-following walk with uniform teleportation. Finish with Stationary-vector verification: the full damped residual is the correct equation to test, while the raw `||Pr-r||1` value is intentionally labelled as a diagnostic rather than a pass/fail stationary condition.

## 5. Run the four controlled experiment tabs

Network effect is the link-change comparison. Damping sweep keeps the graph and tolerance fixed while comparing `d = 0.5, 0.7, 0.85, 0.95`; avoid claiming that a larger d must always increase one page's score or always take more iterations. Tolerance sweep compares the three required tolerances with a stricter `1e-12` iterative reference. Dangling pages shows the corrected uniform column and then the changed ranking after adding one outgoing link. Verification shows the transition columns, score sum, nonnegativity/finiteness, convergence, and both residuals as explicit checks.

## 6. Close on implementation credibility

Mention that `src/engine/pagerank.ts` is separate from the React components and that the unit tests cover matrix construction, dangling handling, a single-page graph, disconnected components, normalization, convergence, stationary residual behavior, and invalid parameters. The important viva sentence is: “The interface is only a view of the vectors and matrices generated by the engine; final ranking values and convergence data are never hardcoded.”
